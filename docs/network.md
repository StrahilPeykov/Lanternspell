# Shared session authority

`server/index.ts` runs the same `src/simulation/battle.ts` rules as local solo. The Cloudflare Vite plugin runs a real local workerd Durable Object with SQLite; production configuration declares one `Campaign` object per opaque session ID and a SQLite migration. No Cloudflare account or external resources were used. Deployment is not authorized and actual account Free configuration remains unverified. There is no deployment script, paid API, runtime generation or external dependency on the resolution path.

## Contract

`POST /api/session` returns `{sessionId,token,invitation,seat}`. `POST /api/session/:id/join` consumes the invitation once and returns the second seat credential. The game uses a URL fragment for invitations; the fragment is not sent with the page request. Rejoin retains the seat token. Browser WebSockets authenticate using `wizard-v1` and `seat.<opaque token>` subprotocols, keeping credentials out of query strings. Tokens are not logged or included in snapshots. Shared and solo saves remain distinct.

All commands carry `version:1`, an opaque `commandId`, and a discriminated `kind`. Maximum message length is 4096 characters; each socket is capped at 30 messages per second. Inputs validate type, finite positions, world bounds, action names, and string lengths. Origin must match. Outside localhost, the client requires HTTPS/WSS. This prototype is not public service hardening: before any publication, verify account Free settings and add abuse controls for unauthenticated session creation and maximum campaign lifetime. Do not treat local passing tests as permission to publish.

The durable payload holds quest stage, safe positions, battle, current legal plans, per-seat plan revisions, ready keys, encounter consents, most recent committed presentation result, bounded reward IDs, and the last 128 important acknowledgements. SQLite `transactionSync` commits a new state and acknowledgement together without an intervening await. Old round IDs and revisions prevent retried commands beyond the acknowledgement window from resolving a round again. Shared interactions have stage preconditions, so replay cannot duplicate quest outcomes.

Battle revision changes only on authoritative round resolution. A plan edit increments only that seat's plan revision, allowing both seats to submit concurrently against the same battle revision. The joint key includes battle ID, round, and both plan revisions. Any edit clears both readiness confirmations. Both seats must confirm that exact key. A living mage must have a valid plan; a downed mage's player still reviews and confirms the queue. Fixed battle timing, never arrival order, determines action order. One synchronous call computes and commits the complete state/events before clients animate.

Both authenticated participants must be connected for quest decisions or round confirmation. Each player independently consents near an encounter marker, so local dialogue can remain open until that player's own action. Disconnection clears readiness/encounter consent and pauses shared decisions. Rejoin restores the seat and authoritative state; first reconnect snapshot does not replay old cinematics. Replacing a connection cannot add a third seat. No server simulation loop, animation timers, heartbeats or alarms are used.

`acceptWebSocket` plus `serializeAttachment` implements the Hibernation API. The constructor restores state from SQLite and movement metadata from socket attachments after eviction. Movement is immediate locally, sent at most 10 Hz only when requested, and interpolated by the renderer. Server caps movement rate and displacement (7 m/s plus a small tolerance, maximum 5 m per update), accepts only the zone bounds, and does not persist each movement update. Important commands and disconnect save current safe positions. Snapshot decisions are immutable from presentation's perspective; motion/effects never apply damage.

`SharedClient` keeps a bounded 32-command pending queue with stable retry IDs, measures acknowledgements, drops obsolete movement under backpressure, and rejects queue growth beyond 64 KB. Read-only local dialogue/journal needs no network command. `applicationDelayMs` can delay receipt handlers during development; this simulates application delay only, not packet loss or actual geographic latency.

## Local evidence and resume commands

From the project root, run `npm run dev` (port **5180**; 5173 belongs to a pre-existing unrelated app and was left alone). Run `npx vitest run tests/network.test.ts` for 10 reducer/model tests, including 200 generated command sequences. Run `node tests/network-real.mjs` for two independent Chromium contexts using actual browser WebSockets against this local server. Set `GAME_URL` to test another local build URL. The script never mocks sockets or inserts campaign state. It sends real protocol commands; it is intentionally not evidence that gameplay UI paths were exercised.

`evidence/network-real.json` records accepted simultaneous planning; edit-after-ready and stale-key rejection; disconnect before result and after commit; seat resume; duplicate confirm; stale-round rejection; legal teaching victory and one reward. Command timings include Playwright polling overhead and localhost scheduling, not internet latency. Authoritative unit fixtures in `tests/network.test.ts` are explicitly labelled arranged state. `evidence/network-reconstruction.json` verifies a real server process stop/restart followed by both saved seat credentials restoring the same committed battle, revision, quest stage and reward IDs from SQLite. Reproduce with `$env:KEEP_STATE='1'; node tests/network-real.mjs`, stop and restart this project's server, then `$env:REJOIN='1'; node tests/network-real.mjs; $env:REJOIN=$null; $env:KEEP_STATE=$null`. The temporary credential file lives under ignored `.wrangler/` and is deleted after a successful rejoin check. For application receipt delay, use `$env:APPLICATION_DELAY_MS='250'; node tests/network-real.mjs; $env:APPLICATION_DELAY_MS=$null`; delayed evidence has its own file. This 250 ms application-delay test passed.

The production build passed `npm run build`. Start its real local worker and packaged assets with `npx vite preview --host 127.0.0.1 --port 5181`. In a second terminal run `$env:GAME_URL='http://127.0.0.1:5181'; $env:EVIDENCE_FILE='evidence/network-production.json'; node tests/network-real.mjs`. That production protocol scenario passed, additionally checking cross-origin creation, malformed join input, and consumed-invitation rejection. A first preview correctly rejected the transient 35.6 MiB character asset; the art pass reduced it to 3.5 MB and the subsequent preview passed. UI gameplay, visual motion, and two-device internet tests remain separate evidence requirements.
